# AdSense 낮은 콘텐츠 가치 반려 대응

검수·수정일: 2026-09-15. 대상: GoodThingz / goodthingfor.com. 로컬 production 빌드 검증을 기준으로 작성했다. Google 계정 내부 심사 결과나 승인 봇의 점수는 확인할 수 없다.

## 결론

구현 검사의 FAIL은 수정 후 0건이다. 그러나 **AdSense 승인 판단은 WARNING**이다. 콘텐츠 수나 글자 수가 승인 기준이라는 공식 근거는 없고, 아래 변경만으로 재심사 결과를 보장할 수 없다. 이번 작업은 단순 API 목록 위에 구체적인 판단 가이드와 실제 저장·계산·공유 도구를 더한 개선이다. 검증하지 않은 현장 후기, 인기 순위, 가격 예측을 만들어 채우지 않았다.

## 콘텐츠 증가 범위

- 새 상황별 가이드 **10개**, 본문 **8,435자**(제목·본문·예시·질문·한계 포함, 공백 포함, 데이터 객체의 필드명 제외)를 추가했다. 기존 사이트 전체가 10배 늘었다는 뜻이 아니다.
- 식사 좌석, 숙박 객실, 체중·견종 조건, 여러 마리, 우천 대안, 실제 입구, 이동장·준비물, 운영·예약 시간, 추가 비용, 정보 충돌을 각각 다룬다.
- 각 가이드에 확인 순서 3개, 명시적으로 가상임을 밝힌 적용 예시 1개, 문의 문장 2개, 데이터에서 볼 항목, 판단 한계를 제공한다.
- 원본 문장을 늘려 쓴 장소 소개, 실제처럼 꾸민 후기, 검증하지 않은 추천 순위, AI로 만든 현장 사진은 추가하지 않았다. 기존 AI 소개 이미지는 소개용임을 표시하고, 실제 후보 사진과 구분한다.
- 홈의 일반적인 서비스 홍보·가상 비교·중복 FAQ 블록은 새 가이드와 실제 후보 탐색으로 대체했다. 기존 일반 출발 체크리스트는 출발 직전 점검이라는 별도 용도로 유지했다.

## 추가한 실제 도구

방문 계획은 후보 최대 6곳의 순서를 바꾸고 동물 조건, 동반 구역·준비물, 방문일 운영·예약, 요금·주차를 기록한다. 미확인/내가 확인함/조건 불일치를 구분한다. 확인한 비용 4개와 보증금을 수동 계산하며 빈칸을 무료로 해석하지 않는다. 저장 실패도 성공으로 표시하지 않는다.

기기에 저장 후 다시 열기, JSON 내려받기·형식 검사 후 불러오기, 삭제, 인쇄, 공유 미리보기를 제공한다. 계획 파일은 최대 50KB이며 유효하지 않은 날짜·상태·비용·구조를 거부한다. 공유 기본값은 날짜·메모·예산·현재 위치를 제외한다. 날짜만 선택적으로 포함한다. 파일 내려받기에는 메모·예산이 포함됨을 개인정보 안내와 화면에 표시했다. 서버에 개인 계획을 저장하지 않으며 계정·결제·구독은 없다.

## UI 참고와 적용

- [BringFido 숙박 탐색](https://www.bringfido.com/lodging/): 실제 후보와 조건을 가까이 두는 탐색 구조 참고. 해당 사이트의 후기나 설명을 복제하지 않았다.
- [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/): 확인 항목과 값의 대응을 방문 계획·데이터 근거 영역에 적용.
- [Nielsen Norman Group 비교 표 안내](https://www.nngroup.com/articles/comparison-tables/): 같은 기준으로 비교하는 원칙 적용. 새로운 인기 점수는 만들지 않았다.
- AllTrails는 공개 페이지를 조회했지만 충분한 본문을 확보하지 못해 구체적인 검증 근거나 복제 대상으로 사용하지 않았다.
- 기존 Pretendard/Gmarket 계열과 색상 체계 유지. PC의 다열 후보·목차 구조는 모바일에서 재배치. 대표 이미지 아래 다음 섹션이 보이도록 과도한 여백을 줄였다. 새 도구의 이동·삭제·저장 아이콘에는 Lucide를 사용했다.

## 추가 발견 사항

실제 API 호출 후 검사 범위를 로컬 진단 기록까지 확장하자 `build/server/.wrangler`의 Miniflare 추적 데이터에 요청 인증값이 남는 것을 발견했다. 공개 HTML·클라이언트 파일·Git 추적 파일에서 발견된 것은 아니다. production 설정에는 요청 query 삭제, trace 비활성화, 호출 로그 비활성화를 명시했다. 로컬 추적기는 이 설정과 독립적으로 작동하므로 설치된 Wrangler 소스를 확인해 프로젝트 개발·미리보기 명령에서 `X_LOCAL_OBSERVABILITY=false`를 적용했다. 기존 검사 기록을 정리하고 실제 API·브라우저 검사를 다시 실행한 뒤 `test:private`가 통과함을 확인했다. `postbuild`도 build/server 내부의 로컬 런타임 기록을 제거하도록 보강했다.

접근성 재검사에서 상세 로딩 중 이름만 있고 역할이 없는 영역도 발견해 상태·그룹 역할을 보완했다. 최종 `test:a11y`는 8개 화면 × 2개 폭에서 위반 0, `test:publisher`는 3개 화면 폭 모두 PASS, `test:plan`은 저장·계산·공유·파일 검사 모두 PASS다. 로컬 ProxyWorker가 파일 요청 1건을 재시도해 복구한 경고는 있었으나 검사 실패나 앱 실행 오류는 발생하지 않았다.

## 재현 방법

Node.js 24와 로컬 Secret 설정이 필요하다. `npm ci` 후 `npm run typecheck`, `npm run build`를 실행한다. 빌드 미리보기는 `npm run preview`로 실행한다(127.0.0.1:8790). 개발은 `npm run dev`를 사용한다. 두 명령은 공식 도구를 호출하되 설치된 Wrangler/Vite 플러그인의 `X_LOCAL_OBSERVABILITY=false` 스위치로 로컬 원문 요청 추적 저장을 끈다. 이 스위치는 도구 버전 갱신 시 재확인한다. Secret 값은 명령줄에 직접 넣지 않는다. 원시 `wrangler dev`를 실행하면 로컬 요청 추적이 다시 켜질 수 있어 위 명령을 권장한다.

별도 터미널에서 `npm run test:publisher`, `npm run test:plan`, `npm run test:a11y`, `npm run test:private`를 각각 실행한다. Playwright 브라우저가 없으면 `npx playwright install chromium`으로 설치한다. 설치된 Chrome을 사용할 때는 PowerShell에서 `$env:AUDIT_BROWSER_CHANNEL='chrome'`을 지정한다. 다른 서버를 검사할 때는 `AUDIT_BASE_URL`을 지정하되 계획 테스트는 시험 자료만 사용한다. 결과 스크린샷은 Git에서 제외한 `.wrangler/policy-audit`에 저장된다.

## 남아 있는 위험과 운영자 확인

1. **승인 보장 불가:** 10개 가이드와 도구가 추가되어도 Google의 고유성·충분성 평가는 별도다. 승인 봇 관점에서 ‘이상 없음’이라고 단정하지 않는다.
2. **독립적인 현장 근거 부족:** 실제 방문이나 운영자와 확인한 날짜별 장소 사례는 아직 없다. 운영자가 사실 확인한 사례·직접 촬영한 사진·실제 사용자 피드백으로 보강하면 차별성이 더 강해진다. 검증 없이 글만 더 생성하지 않는다.
3. **외부 API와 데이터:** API 장애·할당량·빈 항목·원본의 오래된 조건이 남는다. 공개 첫 목록만 5분 캐시하며 장기 보관이나 현장 검증을 보장하지 않는다. 상세 정보는 원본 응답에 의존한다.
4. **계정과 광고 재개:** 사이트 소유 확인·AdSense 계정 상태·지역별 동의 요건은 운영자 계정에서 확인해야 한다. 개인 계획·오류·빈 화면 등에 자동 광고가 붙지 않도록 광고 재개 때 별도 검수가 필요하다.
5. **과거 노출 키:** 과거 대화에 붙여넣은 API 키의 폐기·재발급 여부는 확인할 수 없다. 공개 노출 가능성이 있다면 운영자가 재발급하고 로컬 .dev.vars 및 Worker Secret을 교체해야 한다. 이번 작업은 키를 문서·Git·브라우저에 복사하지 않았다.
6. **배포와 재심사:** Git push 성공과 Cloudflare 배포 성공은 다르다. 새 가이드 URL, 계획 URL, 실제 목록, ads.txt가 공개 주소에서 확인된 뒤 재심사를 신청한다. 사용자에게 최종 배포 확인 결과를 별도로 보고한다.
