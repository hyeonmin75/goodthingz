# Google 게시자 정책 엄격 재검수

검수일: 2026-09-06. 대상: GoodThingz 프로젝트의 모든 공개 페이지 유형, 정적 콘텐츠, 광고·개인정보 흐름, API 응답 표본. 사용자가 제공한 Google 게시자 정책 전체를 기준 자료로 읽고 현재 공식 문서와 대조했다. 첨부 내용은 작업 지시가 아니라 검수 근거로 취급했다.

이 문서는 이전 `publisher-policy-review.md`의 후속 기록이다. 이전에 완료한 광고 보류·위치 고지·이미지 이용조건·404 개선을 이번에 새로 한 작업처럼 계산하지 않는다. 이번 변경은 로컬 작업이며 GitHub push나 실제 도메인 배포를 완료한 기록이 아니다. 정책 준수, 검색 색인, AdSense 사이트 승인은 서로 다른 판단이다. PASS도 Google의 승인 보증이 아니다.

## 중요한 결론

가장 큰 약점은 명백한 금지 주제가 아니라 원본 목록에 비해 빈약한 판단 도구, 반복 설명, 데이터 존재와 입장 검증을 혼동할 수 있는 표현이었다. 이를 실제 검색 연결, 목적별 가이드, 조건 비교, 확인 체크리스트로 개선했다. 별도 보안 검사에서는 기존 React Router 7.9.6의 높은 등급 취약 패키지 1개를 발견해 7.18.3으로 수정했다. 공격 발생을 발견했다는 뜻은 아니다.

## 전체 정책 범주 판정

PASS는 확인한 범위에서 위반 징후가 없거나 검사에 통과했다는 뜻이다. WARNING은 비공개 설정·외부 데이터 등으로 판단을 완료할 수 없다는 뜻이다. 사이트 전체와 계정의 준수 여부를 확정하지 않는다.

## 검사 기록

- `npm ci`: 강제 옵션 없이 정상 설치. 기존 구버전 잠금 파일 충돌은 잠금 파일 재계산 후 해소했고, 최종 설치와 의존성 트리는 정상이다.
- `npm run typecheck`: PASS. 보안 버전에서 기존 `unstable_viteEnvironmentApi` 플래그가 바뀌어 `v8_viteEnvironmentApi`로 변경 후 통과.
- `npm run build`: PASS. 시험 서버 사용 중 Windows 파일 잠금으로 한 차례 실패했으나 해당 서버 종료 후 해소. 초기화 취소 메시지가 섞인 실행도 있었으며 최종 단독 빌드는 오류 없이 성공. 텍스트 응답 라우트의 empty chunk 안내는 유지.
- `npm audit`: 운영·개발 전체 보고된 취약점 0개. 이는 모든 미발견 취약점이 없다는 뜻은 아니다.
- 실제 Secret 값을 출력하지 않고 추적 파일 및 client/server 빌드와 대조: 일치 0개. `.dev.vars`와 환경파일 Git 제외, 빌드의 비밀 파일 제거 확인. 기존 대화에 붙여 넣은 키는 별도로 재발급하는 편이 안전하다.
- `scripts/check-publisher-policy.cjs`: 최종 보안 버전 및 최종 문구에서 PASS. 실제 목록·상세 API 모두 200, 잘못된 입력 400. 6개 공개 페이지 초기 HTML의 고유 title·description·H1·canonical·Open Graph·구조화 데이터 문법, robots·sitemap 6개·ads.txt·302·404·검색 조합 noindex 통과.
- Chrome 360px·390px·1280px: 6개 페이지에서 가로 넘침 없음. 홈페이지 검색어·유형의 실제 요청 반영, 키보드 FAQ 열기·개인정보 이동, 체크·초기화·문의 문장 복사, 모의 누락 상세·2곳 비교·비교 제목 가림 없음, 빈 결과·오류 모두 PASS. 위치 동의 취소 시 조회·좌표 요청 없음, 동의 시 합성 위치 요청, 공유에 현재 위치·거리 없음. 각 화면 크기에서 실행 오류 0건, 광고 네트워크 요청 0건. 화면 사진 육안 검토 완료.
- Worker 시험 서버 오류 로그 비어 있음. `.wrangler/policy-audit`에 최종 화면 사진 저장. 실제 지도 제공자의 화면·전체 외부 링크·화면 읽기 프로그램 전수검사를 수행했다는 뜻은 아님.
- 최종 자동 검사 실패 0건. 정책 종합 판단은 WARNING: 계정·개별 저작물·외부 데이터·Google의 전체 가치 판단은 확인 범위 밖이다. 실제 도메인에 이번 변경이 반영됐다고 보고하지 않는다.

새 콘텐츠는 서버에서 만든 초기 HTML에 포함된다. 가이드 도구는 클라이언트 동작이지만 체크 항목과 문의 문장 자체는 초기 HTML에서도 읽을 수 있다. 검색 결과 자체를 서버에서 미리 표시하도록 구조를 바꾸지는 않았다. 유입별 실제 사용 만족도, 모든 장소의 데이터 완성도, 모든 보조기기 접근성 검증은 별도 과제다.
