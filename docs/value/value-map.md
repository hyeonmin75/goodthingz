# 반려동물 동반여행 서비스 가치 지도

작성일: 2026-08-27

기준 문서: `docs/api/api-spec.md`, `docs/value/user-problems.md`

이 문서는 사용자 문제를 기능 후보와 연결하되, 공공데이터 목록을 많이 보여주는 것을 목표로 하지 않는다. 검색, 필터, 비교, 계산, 지도, 차트, 요약은 실제로 시간을 줄일 때만 가치가 있다. 모든 핵심 기능은 무료이며, 결제·구독·Paywall·Premium 잠금 기능은 만들지 않는다.

## 가치 판단 기준

| 기준 | 의미 |
| --- | --- |
| 검색 시간 감소 | 사용자가 갈 만한 후보를 찾는 데 걸리는 시간을 줄이는가 |
| 비교 시간 감소 | 후보 여러 개를 조건별로 비교하는 시간을 줄이는가 |
| 판단 시간 감소 | 실제로 갈지 말지 결정하는 시간을 줄이는가 |
| 실패 비용 감소 | 현장 거절, 헛걸음, 조건 오해를 줄이는가 |
| API 적합도 | 현재 API 원본으로 구현 가능한가 |
| 신뢰성 | 부족한 정보를 과장하지 않고 표시할 수 있는가 |

| --- | --- | --- | --- | --- |
| 주말 당일 외출 보호자 | 지금 가까운 곳 중 반려동물과 갈 만한 곳을 빠르게 골라야 함 | 위치, 거리, 주소, 이미지, 전화번호, 반려동물 조건 | 실시간 영업, 실제 입장 가능 여부, 최신 후기 | 현위치 지도, 거리순 5개 추천, 조건 요약, 전화 확인 표시 |
| 1박 이상 여행 계획자 | 숙소·식사·관광을 함께 성립시켜야 함 | 지역별 장소, 타입, 좌표, 숙박/관광/음식점 구분 | 예약 가능 여부, 가격, 실제 이동시간 | 지역별 여행 밀도, 타입별 필터, 후보 지역 비교, 숙소 주변 반경 검색 |

| 숙박 중심 여행자 | 숙박과 주변 일정을 함께 판단해야 함 | 숙박 타입, 입실/퇴실, 주차, 예약안내, 주변 장소 좌표 | 객실별 가능 여부, 가격, 예약 상태 | 숙소 주변 장소 수 계산, 주변 일정 묶음, 숙박 조건 요약 |
| 콘텐츠 운영자 | 지역별 콘텐츠 후보와 갱신 대상을 찾아야 함 | 수정일, 표출 여부, 이미지, 지역/분류 코드 | 검색 수요, 실제 방문 품질, 계절성 | 최근 수정 목록, 이미지 유무 필터, 지역별 타입 차트 |

## 기능별 시간 절감 효과

| 기능 유형 | 줄이는 시간 | 적용 가치 | 주의점 |
| --- | --- | --- | --- |
| 검색 | 후보를 처음 찾는 시간 | 키워드, 지역, 현재 위치 검색 | 검색 결과가 많을수록 좋은 것이 아니라 조건이 맞는 결과가 중요 |
| 필터 | 맞지 않는 후보를 제거하는 시간 | 타입, 지역, 거리, 이미지 유무, 주차/운영 field, 동반 조건 | API field가 비어 있으면 “불가”가 아니라 “정보 없음”으로 처리해야 함 |
| 지도 | 위치 관계를 이해하는 시간 | 현재 위치 주변, 숙소 주변, 지역별 분포 | 지도만 보여주면 목록과 다르지 않으므로 조건 요약과 함께 써야 함 |
| 비교 | 후보 2~5개를 나란히 보는 시간 | 거리, 주소, 운영정보, 주차, 동반 조건, 이미지 | 원본 field를 그대로 나열하지 말고 같은 의미 단위로 정규화해야 함 |
| 계산 | 사람이 직접 세어보는 시간 | 반경 내 장소 수, 타입 다양성, 이미지 보유 여부, 정보 충실도 | 점수가 실제 허용 여부처럼 보이면 안 됨 |
| 차트 | 지역/타입 분포를 파악하는 시간 | 지역별 장소 수, 타입별 장소 비율, 최근 수정량 | 일반 여행자 첫 화면보다는 계획자·운영자에게 적합 |
| 요약 | 긴 텍스트를 읽는 시간 | 반려동물 조건, 준비물, 주차, 운영시간, 주의사항 | 요약은 원문 근거를 벗어나 추측하면 안 됨 |

## API 원본으로 바로 가치가 나는 데이터

| 데이터 | 사용자 가치 |
| --- | --- |
| `mapx`, `mapy`, `dist`, `radius` | 가까운 장소를 빠르게 찾고 이동 부담을 줄임 |
| `addr1`, `addr2`, `zipcode` | 실제 방문 지역과 주소 확인 |
| `title`, `contenttypeid`, `lclsSystm1~3` | 장소 성격 파악과 타입 필터 |
| `firstimage`, `firstimage2`, `detailImage2` | 장소 분위기 판단과 클릭 전 검토 |
| `tel` | 조건이 불확실할 때 바로 확인 |
| `restdate`, `usetime`, `parking`, 타입별 소개정보 | 방문 가능성 판단 |
| `acmpyTypeCd`, `acmpyPsblCpam`, `acmpyNeedMtr`, `etcAcmpyInfo` | 반려동물 동반 가능성과 준비물 판단 |
| `showflag`, `modifiedtime` | 최신성, 표출 여부, 데이터 관리 |

## 원본만으로 부족해서 조심해야 하는 부분

| 부족한 부분 | 서비스에서의 처리 방향 |
| --- | --- |
| 실시간 영업 여부 없음 | “현재 영업 중”으로 단정하지 않고 운영정보와 전화 확인을 제공 |
| 예약 가능 여부·가격 없음 | 예약 서비스처럼 표현하지 않음 |
| 대형견/맹견/다견 허용 여부가 완전 구조화되어 있지 않음 | 원문 조건을 요약하되, 불명확하면 “확인 필요” 표시 |
| 리뷰와 현장 경험 없음 | 만족도 순위처럼 보이는 표현을 피함 |
| 이미지 URL이 없거나 HTTP일 수 있음 | 이미지 없음 상태와 대체 UI 필요 |
| `contentTypeId` 설명이 자료마다 혼재 | API 호출 테스트 후 코드 기준 확정 필요 |
| `/areaCode2`, `/categoryCode2` 자료 불일치 | 구현 기준에서 제외하고 별도 검증 backlog로 관리 |

## 핵심 사용자 문제 우선순위

### 1. “지금 내 주변에서 반려동물과 갈 수 있는 곳을 빠르게 고르고 싶다”

가장 즉시성이 높고, 위치 기반 API와 반려동물 조건 데이터가 바로 연결된다. 현위치 지도, 거리순 정렬, 조건 요약, 전화 확인 표시만으로도 검색 시간과 판단 시간을 크게 줄일 수 있다.

### 2. “반려동물 동반 조건을 읽고 해석하는 시간이 너무 오래 걸린다”

`detailPetTour2`의 반려동물 조건 field가 GoodThingz의 차별점이 될 수 있다. 원문을 그대로 보여주는 대신 동반 가능 동물, 필요사항, 기타 주의사항, 사고 대비사항으로 요약하면 사용자가 헛걸음할 위험을 줄일 수 있다.

### 3. “여행 지역을 고르기 전에 그 지역이 반려동물 여행에 적합한지 알고 싶다”

지역 기반 목록과 타입별 분류를 사용하면 지역별 장소 밀도와 다양성을 계산할 수 있다. 숙박, 음식점, 관광지, 공원성 장소가 함께 있는지 보여주면 1박 이상 여행 계획자의 비교 시간이 줄어든다.

### 4. “숙소 주변에 실제로 같이 갈 곳이 충분한지 확인하고 싶다”

숙박 단독 정보보다 숙소 주변 반경 내 관광지·음식점·산책 가능 장소를 묶어 보여주는 것이 더 큰 가치다. 예약 가능 여부는 없지만, 여행 일정이 성립하는지 판단하는 데는 충분한 도움을 줄 수 있다.

### 5. “정보가 부족하거나 모호한 장소를 피하고 싶다”

반려동물 조건, 전화번호, 이미지, 운영정보, 주차정보가 비어 있는 장소는 실패 위험이 높다. 정보 충실도와 “전화 확인 필요” 표시는 사용자가 불필요한 이동과 검색을 줄이는 데 도움이 된다.

## 우선 구현하지 않아야 할 것

SEO 페이지를 API 레코드 수만큼 자동 생성하는 것은 가치가 낮고 프로젝트 SEO 정책에도 맞지 않는다. 결제, 구독, Paywall, Premium 잠금 기능도 만들지 않는다. 리뷰, 실시간 영업, 예약, 가격처럼 API에 없는 정보를 있는 것처럼 보이게 하는 기능도 만들지 않는다.

초기 MVP는 “무료 고급 UX”를 목표로 하되, 데이터가 말할 수 있는 범위 안에서 정직하게 편리해야 한다. 가장 먼저 검증할 가치는 현위치·지역 검색, 반려동물 조건 요약, 후보 비교, 정보 부족 경고다.
